## 다운로드와 무결성

Git LFS가 설치된 환경에서 통합 제출 저장소를 받는다.

```bash
git lfs install
git clone https://github.com/tmdgns104/Engine_Assembly_Final_Submission.git
cd Engine_Assembly_Final_Submission
git lfs pull
```

- 데이터셋: [ZIP 실파일 직접 다운로드](https://github.com/tmdgns104/Engine_Assembly_Final_Submission/raw/refs/heads/main/docs/M1_M2_dataset_evidence_v002.zip)
- 영상: [MP4 실파일 직접 다운로드](https://github.com/tmdgns104/Engine_Assembly_Final_Submission/raw/refs/heads/main/video/%EC%A0%9C%EC%B6%9C%EC%9A%A9.mp4)

데이터 ZIP은 373,981,270 bytes, SHA-256 `3c991ac98bb6c48141403f7142a7a4dc2ece84f4bf468aa2459039a3f973b42e`다.
영상은 475,576,256 bytes, SHA-256 `fe44c339c4ad7d1ad9e3b6cfdd4651343e7b75d216ee113b9004bde877b0d0e7`다.

100여 바이트의 LFS 포인터를 ZIP이나 동영상 본체로 사용하지 않는다. Code → Download ZIP의 LFS 포함 여부는 이 안내 갱신에서 보증하지 않는다.

[FILE_MANIFEST.json](FILE_MANIFEST.json)은 원본 문서 패키징 당시의 파일별 크기·SHA-256 기록이다. 순환 참조 방지를 위해 manifest 자신과 검증 JSON, 로컬 일괄 ZIP은 해당 목록에서 제외했다. 이후 추가된 영상과 안내 문서 수정은 이 과거 목록을 덮어쓰지 않고 Git 이력과 [영상 안내](../video/README.md)로 구분한다.

## 검증의 범위

[PACKAGING_VERIFICATION.json](PACKAGING_VERIFICATION.json)은 기존 **자료 정리·무결성·로컬 조회 검증** 기록이다. 당시 승인 문서 해시·쪽수, 편집본 대응, 원본 ZIP CRC/내부 manifest, 보조자료 보존, DB 조회와 문서 링크 결과를 확인할 수 있다.
과거 84개·47개 점검을 이번에 다시 실행했다고 주장하지 않는다. 원문 실패·중단·REVIEW·ERROR·PENDING 기록과 초안·별도 승인 이력을 유지했다.

최종 제출 영상은 현재 `video/제출용.mp4`로 제공한다. 이번 갱신은 영상 접근과 통합 제출 안내를 정리한 작업이며, 새 실험·학습·모델 변환·Jetson/PLC 시험을 수행하지 않았다. 발표용 PPT/PPTX의 포함 여부는 별도 확인 대상이다.
